# ui — เว็บแดชบอร์ดคุมทุกขั้นตอน (ไม่ต้องจำคำสั่ง CLI)

หน้าเว็บเดียวคุมทั้งสายงาน `probe → เลือกลิงก์ → run → ติ๊กคน → finalize → upload`
ใช้ Node ล้วน **ไม่เพิ่ม dependency ใหม่** และเรียกสคริปต์เดิม (`backup-page.mjs`, `uploader/upload-people.mjs`) ผ่าน API

## เริ่มใช้

ต้องมี **Node 22+** (สคริปต์เช็คให้ตั้งแต่เปิด) และติดตั้ง dependency ของขั้น upload ครั้งเดียว:

```bash
cd uploader && npm install && cd ..
```

```bash
# 1) เปิด Chrome ให้ login ค้างไว้ (แบบเดียวกับที่ CLI ใช้)
#    --remote-allow-origins=* จำเป็นสำหรับ Chrome 111+ · ดูคำสั่งครบทุก OS ใน README.md หัวข้อ "สิ่งที่ต้องมี"
# macOS
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --remote-debugging-port=9333 --remote-allow-origins=* --user-data-dir="$HOME/.chrome-cdp-9333"
# Linux
google-chrome --remote-debugging-port=9333 --remote-allow-origins=* --user-data-dir="$HOME/.chrome-cdp-9333"
# Windows cmd: start "" "%PROGRAMFILES%\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9333 --remote-allow-origins=* --user-data-dir="%USERPROFILE%\.chrome-cdp-9333"

# 2) รันเซิร์ฟเวอร์ UI
node ui/server.mjs            # เปิด http://localhost:4173
node ui/server.mjs --port 5000
```

เปิดเบราว์เซอร์ที่ `http://localhost:4173` แล้วทำตามการ์ด 1 → 9

## แดชบอร์ดทำอะไรได้ (เทียบกับ CLI)

| การ์ด | ทำอะไร | คำสั่ง CLI ที่รันให้เบื้องหลัง |
|---|---|---|
| 1 วาง URL | ลาก `urls.txt` มาวาง หรือพิมพ์/วาง URL · ตั้ง “ชื่อหน่วยงานปลายทาง” ต่อ URL | เขียน `urls.txt` · `source-groups.json` |
| 2 Probe | สแกนหาลิงก์ + นับรูป (ยังไม่โหลด) | `backup-page.mjs --probe --from urls.txt --out ./out` |
| 3 เลือกหน้า | ติ๊กลิงก์ที่จะโหลด แล้วบันทึก | เขียน `out/_staging/picked-links.json` |
| 4 ติ๊กรวม | ติ๊กครั้งเดียวใช้ทุกหน้า (รูปซ้ำ) | เขียน `master.json` · `--apply-master` |
| 5 เลือกรูป/หน้า | ตัดไอคอน/ป้ายก่อนโหลด | เขียน `out/_staging/<slug>/picked-images.json` |
| 6 Run | ดึงหน้าจริง + รูปลง `out/<slug>/` | `backup-page.mjs --run --from out/_staging/picked-links.json …` |
| 7 ติ๊กคน | ติ๊กรูปคน (คลิกที่ตัวการ์ดก็ติ๊กได้) + ลากจัดลำดับ + ตั้งเลขตำแหน่งภาพ | เขียน `out/<slug>/review/selection.json` |
| 8 Finalize | ตัดรูปที่ไม่ติ๊ก + สร้าง `people.json` สุดท้าย | `backup-page.mjs --finalize --all --compact-orders` |
| 9 Upload | ต่อคิวจากไฟล์ที่ลากวาง แล้วรันทีละรายการตามลำดับคิว (dry-run ก่อน แล้วค่อยยิงจริง) | `upload-people.mjs --from out/<slug>/people.json [--save --i-verified]` |

ทุกงานรันเป็นโปรเซสลูก และ **log สด** อยู่แถบล่างจอ (ปุ่ม ■ หยุด ได้)

## คิวอัปโหลด (การ์ด 9)

- **ลาก `people.json` มาวางได้หลายไฟล์พร้อมกัน** → เซิร์ฟเวอร์วางไว้ใน `out/<slug>/` ให้ แล้ว **ต่อท้ายคิวตามลำดับที่วาง**
  (ชุดที่มีไฟล์พังไฟล์เดียว = ปฏิเสธทั้งชุด ไม่เขียนอะไรเลย · slug ซ้ำในชุดเดียว = ปฏิเสธ)
- **ลากแถวในคิว** เพื่อสลับลำดับก่อนรัน · ปุ่ม ✕ เอารายการออก · “เพิ่มทุกหน้าจากตาราง” ดึงทุกหน้าที่มี `people.json` เข้าคิว
- **ตรวจทั้งหมดตามลำดับ (dry-run)** และ **ยิงจริงทั้งหมด…** → รันเป็น child process **ทีละรายการตามคิว** ในสตรีม log เดียว
  (มีหัวข้อคั่น `===== [2/5] slug =====` และ badge ความคืบหน้า)
- **ถ้ารายการใดล้ม คิวจะหยุดทันที** ไม่ข้ามไปตัวถัดไป
- **คิวอยู่ในหน่วยความจำของหน้าเว็บเท่านั้น** — รีเฟรชแล้วคิวหาย (แต่ job ที่กำลังรันอยู่ทำงานต่อฝั่งเซิร์ฟเวอร์)
  เพราะการเขียนคิวลงดิสก์ไม่ใช่การกดปุ่มสั่งของคน

## เปลี่ยนชื่อหน่วยงานปลายทาง (rename)

- **แก้ได้ 2 ที่ เขียนไฟล์เดียวกัน**: การ์ด 1 (URL ↔ ชื่อหน่วยงาน) และช่องในแถวคิวของการ์ด 9 — พิมพ์ที่ไหนอีกช่องซิงก์ตามทันที แล้วกด **“บันทึกชื่อหน่วยงาน”** ครั้งเดียว
- **มีผลทั้งหัวข้อและปลายทาง**: ชื่อที่ตั้งจะกลายเป็นหัวข้อการ์ด 6/7/9 (slug โชว์เป็นบรรทัดย่อย) และตอนยิงจริงจะ *ใช้/สร้างแผนก* บน backend ตามชื่อนั้น
- **กลไก**: `source-groups.json` → `{ map: { "<URL>": "<ชื่อหน่วยงาน>" } }` · uploader อ่านตอนรันผ่าน `resolveTargetGroup()` → **ไม่ต้องแก้อะไรในตัว uploader เลย**
- **เว้นว่าง = ลบชื่อ** กลับไปใช้ชื่อเดิมจาก slug · พิมพ์ค้างไว้แล้วรีเฟรช ค่าไม่หาย แต่ยังไม่เขียนไฟล์จนกว่าจะกดบันทึก
- **ชื่อซ้ำกับแผนกที่มีอยู่**: ระบบ **เตือนจากผล dry-run จริง** (“เข้าแผนกที่มีอยู่: X” / “จะสร้างแผนกใหม่: X”) แต่ยังยิงจริงได้ — กด “ตรวจทั้งหมดตามลำดับ” ก่อนเพื่อดูให้ชัด
- **กันไว้แล้ว**: 1 URL = 1 ชื่อ (คีย์ทับซ้อนแบบ substring ถูกปฏิเสธ) · ชื่อยาวเกิน 80 หรือขึ้นต้นด้วย `_` ถูกปฏิเสธ · ชุดที่มีแถวไม่ผ่าน = **ไม่เขียนไฟล์เลย**
- **ข้อควรระวัง**: แถวเดิมที่เคยสร้างไว้ใต้ชื่อเก่าบน backend ยังอยู่ (ต้องลบเอง ขั้นตอน 6) · ถ้าไปตั้งชื่อที่ตรงกับแผนกที่มีอยู่ ข้อมูลจะไปรวมกับแผนกนั้น

## ติ๊กให้ง่ายขึ้น (การ์ด 4, 5 และ 7)

- **คลิกที่ตัวการ์ดที่ไหนก็ได้ = ติ๊ก/ยกเลิก** — ใช้เหมือนกันหมดทั้งการ์ด 4 (ติ๊กรวม), 5 (เลือกรูป/หน้า) และ 7 (ติ๊กคน)
- **ช่องติ๊ก (checkbox) ถูกซ่อนแล้ว** — อ่านสถานะจากตัวการ์ด: **พื้นน้ำเงินอ่อน + กรอบน้ำเงิน** = เลือกไว้
- **ยังใช้คีย์บอร์ดได้**: `Tab` ไปที่การ์ด แล้วกด `Space` = ติ๊ก/ยกเลิก (การ์ดที่โฟกัสมีวงแหวนน้ำเงิน)
- คลิกที่ช่อง “ตำแหน่งภาพ”, ปุ่ม, หรือช่องกรอกอื่น **ไม่ติ๊กซ้ำ** (ทำงานตามปกติ)
- ลากการ์ดเพื่อจัดลำดับยังใช้ได้เหมือนเดิม (คลิกที่ตามหลังการลากจะถูกกลืน ไม่ติ๊กพลาด)

## Drag & drop

- **ลาก `urls.txt`** มาวางในการ์ด 1 → โหลด + บันทึกให้ทันที
- **ลาก `people.json`** (หลายไฟล์ก็ได้) มาวางในการ์ด 9 → เข้าคิวรอเลย ใช้กรณีเตรียมไฟล์มาแล้ว
- **ลากการ์ดรูปในขั้นตอน 7** และ **ลากแถวในคิวขั้นตอน 9** เพื่อจัดลำดับ → เลขกำกับอัปเดตตามให้อัตโนมัติ

## ความปลอดภัย (สองชั้นก่อนยิงจริง)

1. กด **ตรวจ (dry-run)** → ได้ report ว่าอะไรจะถูกสร้าง/ข้าม/ล้ม พร้อมเลข (ต่อหน้า หรือ “ตรวจทั้งหมดตามลำดับ”)
2. กด **ยิงจริง…** → ต้อง **ติ๊กยืนยัน i-verified** และ **พิมพ์ให้ตรงเป๊ะ** อีกครั้งจึงยิง
   (ยิงทีละหน้า = พิมพ์ slug · ยิงทั้งคิว = พิมพ์ `ยิงจริง` ครั้งเดียว ดูรายการทั้งคิวในกล่องยืนยัน)
   เซิร์ฟเวอร์ตรวจซ้ำฝั่งหลังบ้านทั้ง `--i-verified` และคำยืนยันของคิว — ไม่ผ่านก็ไม่สตาร์ทแม้แต่รายการแรก

## ขอบเขตการเขียนไฟล์

เหมือน CLI ทุกประการ — เซิร์ฟเวอร์เขียนไฟล์**เฉพาะเมื่อกดปุ่มสั่ง** (บันทึก/รัน) เท่านั้น
หน้าจออย่างเดียวไม่อัปเดตไฟล์ให้ · ไม่แตะไฟล์นอกโปรเจกต์ · ไม่มีรหัสผ่านถูกเก็บ

## หมายเหตุ

- โปรเซสที่รันจาก UI จะได้ `--no-cf-manual` (stdin ไม่ใช่ TTY จึงหยุดรอคนกดไม่ได้)
  ถ้าเจอ Cloudflare ให้แก้ Turnstile ในหน้าต่าง Chrome ที่เปิดค้างไว้เอง แล้วรอ `cf-wait` ให้ครบ
- ปุ่มรีเฟรช (มุมขวาบน) อ่านสถานะจากดิสก์ใหม่ทุกครั้ง — ใช้หลังแก้ไฟล์ด้วยมือได้

## รูปลักษณ์ — ธีม “ระเบียนราชการ”

- **พื้นหลัง** เป็นกระดาษมีเส้นบรรทัด + เส้นขอบซ้ายแบบฟอร์มราชการ · **การ์ด** เป็นแผ่นกระดาษลอย (เงานุ่มอย่างเดียว ไม่มีกรอบซ้อนกับเงา)
- **ความหมายของสี**: หมึกน้ำเงิน = เลือก/ปุ่มหลัก · **แดงตราประทับ = เฉพาะสิ่งที่ย้อนกลับไม่ได้** (ยิงจริง) · เขียว = ตรวจแล้วผ่าน · เหลืองอำพัน = ต้องระวัง
- **รางสถานะด้านบน**: เลขขั้น 1–7, ขั้นที่เสร็จเป็นตราถูก, ขั้นปัจจุบันมีจุดเต้นช้า ๆ, และมีเส้นบอกความคืบหน้าด้านล่างราง
- **ติ๊กการ์ดรูป** = ตราประทับถูกโผล่มุมการ์ด (~200ms) พร้อมพื้นน้ำเงินอ่อน · ยังใช้ `Tab` + `Space` ได้
- **ปุ่มยิงจริง** จะติดสถานะ “พร้อมยิง” (วงแหวนแดงเต้นช้า) เมื่อพิมพ์คำยืนยันตรงเท่านั้น — เป็นการเตือนครั้งสุดท้ายก่อนเขียนลง backend
- **คอนโซล log** เป็นเทปสีเข้มมีรอยปรุด้านบน + ขอบเข้าเล่มด้านซ้าย, pill สถานะกระพริบเฉพาะตอนงานรัน
- **ไอคอนทั้งหมดวาดเป็น SVG** (ไม่มี emoji/สัญลักษณ์แทนไอคอน) · ตัวเลขใช้ tabular figures
- **เข้าถึงได้**: โฟกัสมองเห็นชัดทุกจุด, ทุกคู่สีผ่าน WCAG AA, และปิด motion อัตโนมัติเมื่อเครื่องตั้ง `prefers-reduced-motion`
- **ฟอนต์**: Sarabun โหลดจาก Google Fonts (ถ้าออฟไลน์จะถอยไปใช้ฟอนต์ในเครื่องเอง) — อยากกลับไปใช้ฟอนต์ระบบเดิมให้ลบบรรทัด `<link ... Sarabun ...>` ใน `ui/index.html`
- **ไม่เพิ่ม dependency ในโค้ด**: ยังเป็น Node stdlib ล้วน มีแค่ลิงก์ฟอนต์ที่โหลดผ่านเน็ต
