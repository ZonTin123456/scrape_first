# ui — เว็บแดชบอร์ดคุมทุกขั้นตอน (ไม่ต้องจำคำสั่ง CLI)

หน้าเว็บเดียวคุมทั้งสายงาน `probe → เลือกลิงก์ → run → ติ๊กคน → finalize → upload`
ใช้ Node ล้วน **ไม่เพิ่ม dependency ใหม่** และเรียกสคริปต์เดิม (`backup-page.mjs`, `uploader/upload-people.mjs`) ผ่าน API

## เริ่มใช้

```bash
# 1) เปิด Chrome ให้ login ค้างไว้ (แบบเดียวกับที่ CLI ใช้)
start "" "C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9333 --user-data-dir="C:\ChromeCDP9333"

# 2) รันเซิร์ฟเวอร์ UI
node ui/server.mjs            # เปิด http://localhost:4173
node ui/server.mjs --port 5000
```

เปิดเบราว์เซอร์ที่ `http://localhost:4173` แล้วทำตามการ์ด 1 → 9

## แดชบอร์ดทำอะไรได้ (เทียบกับ CLI)

| การ์ด | ทำอะไร | คำสั่ง CLI ที่รันให้เบื้องหลัง |
|---|---|---|
| 1 วาง URL | ลาก `urls.txt` มาวาง หรือพิมพ์/วาง URL | เขียน `urls.txt` |
| 2 Probe | สแกนหาลิงก์ + นับรูป (ยังไม่โหลด) | `backup-page.mjs --probe --from urls.txt --out ./out` |
| 3 เลือกหน้า | ติ๊กลิงก์ที่จะโหลด แล้วบันทึก | เขียน `out/_staging/picked-links.json` |
| 4 ติ๊กรวม | ติ๊กครั้งเดียวใช้ทุกหน้า (รูปซ้ำ) | เขียน `master.json` · `--apply-master` |
| 5 เลือกรูป/หน้า | ตัดไอคอน/ป้ายก่อนโหลด | เขียน `out/_staging/<slug>/picked-images.json` |
| 6 Run | ดึงหน้าจริง + รูปลง `out/<slug>/` | `backup-page.mjs --run --from out/_staging/picked-links.json …` |
| 7 ติ๊กคน | ติ๊กรูปคน (คลิกที่ตัวการ์ดก็ติ๊กได้) + ลากจัดลำดับ + ตั้งเลขตำแหน่งภาพ | เขียน `out/<slug>/review/selection.json` |
| 8 Finalize | ตัดรูปที่ไม่ติ๊ก + สร้าง `people.json` สุดท้าย | `backup-page.mjs --finalize --all --compact-orders` |
| 9 Upload | ต่อคิวจากไฟล์ที่ลากวาง แล้วรันทีละรายการตามลำดับคิว (dry-run ก่อน แล้วค่อยยิงจริง) | `upload-people.mjs --from out/<slug>/people.json [--save --i-verified]` |

ทุกงานรันเป็นโปรเซสลูก และ **log สด** อยู่แถบล่างจอ (ปุ่ม ■ หยุด ได้)

## คิวอัปโหลด (การ์ด 9)

- **ลาก `people.json` มาวางได้หลายไฟล์พร้อมกัน** → เซิร์ฟเวอร์วางไว้ใน `out/<slug>/` ให้ แล้ว **ต่อท้ายคิวตามลำดับที่วาง**
  (ชุดที่มีไฟล์พังไฟล์เดียว = ปฏิเสธทั้งชุด ไม่เขียนอะไรเลย · slug ซ้ำในชุดเดียว = ปฏิเสธ)
- **ลากแถวในคิว** เพื่อสลับลำดับก่อนรัน · ปุ่ม ✕ เอารายการออก · “เพิ่มทุกหน้าจากตาราง” ดึงทุกหน้าที่มี `people.json` เข้าคิว
- **ตรวจทั้งหมดตามลำดับ (dry-run)** และ **ยิงจริงทั้งหมด…** → รันเป็น child process **ทีละรายการตามคิว** ในสตรีม log เดียว
  (มีหัวข้อคั่น `===== [2/5] slug =====` และ badge ความคืบหน้า)
- **ถ้ารายการใดล้ม คิวจะหยุดทันที** ไม่ข้ามไปตัวถัดไป
- **คิวอยู่ในหน่วยความจำของหน้าเว็บเท่านั้น** — รีเฟรชแล้วคิวหาย (แต่ job ที่กำลังรันอยู่ทำงานต่อฝั่งเซิร์ฟเวอร์)
  เพราะการเขียนคิวลงดิสก์ไม่ใช่การกดปุ่มสั่งของคน

## ติ๊กให้ง่ายขึ้น (การ์ด 5 และ 7)

- **คลิกที่ตัวการ์ด** = ติ๊ก/ยกเลิก (คลิกที่ checkbox, ช่องตำแหน่งภาพ หรือปุ่ม ยังทำงานตามปกติ ไม่ติ๊กซ้ำ)
- การ์ดที่ติ๊กอยู่ **กรอบน้ำเงิน** พื้นอ่อน badge ในรูปชัดขึ้น · checkbox ใหญ่ขึ้นเป็น 26px
- ลากการ์ดเพื่อจัดลำดับยังใช้ได้เหมือนเดิม (คลิกที่ตามหลังการลากจะถูกกลืน ไม่ติ๊กพลาด)

## Drag & drop

- **ลาก `urls.txt`** มาวางในการ์ด 1 → โหลด + บันทึกให้ทันที
- **ลาก `people.json`** (หลายไฟล์ก็ได้) มาวางในการ์ด 9 → เข้าคิวรอเลย ใช้กรณีเตรียมไฟล์มาแล้ว
- **ลากการ์ดรูปในขั้นตอน 7** และ **ลากแถวในคิวขั้นตอน 9** เพื่อจัดลำดับ → เลขกำกับอัปเดตตามให้อัตโนมัติ

## ความปลอดภัย (สองชั้นก่อนยิงจริง)

1. กด **ตรวจ (dry-run)** → ได้ report ว่าอะไรจะถูกสร้าง/ข้าม/ล้ม พร้อมเลข (ต่อหน้า หรือ “ตรวจทั้งหมดตามลำดับ”)
2. กด **ยิงจริง…** → ต้อง **ติ๊กยืนยัน i-verified** และ **พิมพ์ให้ตรงเป๊ะ** อีกครั้งจึงยิง
   (ยิงทีละหน้า = พิมพ์ slug · ยิงทั้งคิว = พิมพ์ `ยิงจริง` ครั้งเดียว ดูรายการทั้งคิวในกล่องยืนยัน)
   เซิร์ฟเวอร์ตรวจซ้ำฝั่งหลังบ้านทั้ง `--i-verified` และคำยืนยันของคิว — ไม่ผ่านก็ไม่สตาร์ทแม้แต่รายการแรก

## ขอบเขตการเขียนไฟล์

เหมือน CLI ทุกประการ — เซิร์ฟเวอร์เขียนไฟล์**เฉพาะเมื่อกดปุ่มสั่ง** (บันทึก/รัน) เท่านั้น
หน้าจออย่างเดียวไม่อัปเดตไฟล์ให้ · ไม่แตะไฟล์นอกโปรเจกต์ · ไม่มีรหัสผ่านถูกเก็บ

## หมายเหตุ

- โปรเซสที่รันจาก UI จะได้ `--no-cf-manual` (stdin ไม่ใช่ TTY จึงหยุดรอคนกดไม่ได้)
  ถ้าเจอ Cloudflare ให้แก้ Turnstile ในหน้าต่าง Chrome ที่เปิดค้างไว้เอง แล้วรอ `cf-wait` ให้ครบ
- ปุ่ม Refresh (↻) อ่านสถานะจากดิสก์ใหม่ทุกครั้ง — ใช้หลังแก้ไฟล์ด้วยมือได้
